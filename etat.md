## 1. Phase actuelle

**Phase 3 — Automatisation** (mécanisme complet et fonctionnel, cycle de bout en bout opérationnel)

Phases 0 à 2 terminées le 2026-08-27. **Note de méthode (2026-08-27)** : l'auteur a précisé que le contenu (photos/prompts/textes) et la mise en page ne nécessitent pas de validation intermédiaire — seule la mise en ligne finale requiert son accord explicite (conforme à CLAUDE.md). Le cycle complet (génération → email preview → réponse affirmative → mise en ligne automatique) est construit : `scripts/run_publication.sh`, `scripts/check_validation.py`, `scripts/publish.sh`, `.github/workflows/deploy.yml`. Les deux jobs launchd sont **chargés et fonctionnels** (`LastExitStatus = 0`, autorisation macOS accordée). Twilio abandonné le 2026-08-27 (procédure d'inscription bloquante) au profit d'une notification par **email** (Gmail SMTP/IMAP) — voir CLAUDE.md, section Déclenchement automatique. Détail complet dans [automation/AUTOMATISATION.md](./automation/AUTOMATISATION.md).

**Mise à jour du 2026-09-06** : le run automatique headless (déclenché par launchd, sans session interactive) a échoué deux dimanches de suite (30/08 et 06/09) avant de réussir pour la première fois aujourd'hui — trois bugs distincts corrigés dans l'ordre où ils sont apparus (voir journal) : (1) authentification OAuth non rafraîchissable en environnement headless → jeton longue durée (`claude setup-token` / `CLAUDE_CODE_OAUTH_TOKEN`) ajouté au plist **déployé** (`~/Library/LaunchAgents/...`, hors dépôt Git, jamais versionné) ; (2) `--permission-mode acceptEdits` insuffisant pour `curl`/`WebSearch` sans personne pour approuver → `--allowedTools "Bash" "WebSearch"` ajouté à l'invocation dans `scripts/run_publication.sh` ; (3) regex d'extraction de `PREVIEW_DIR:` dans `run_publication.sh` incompatible avec le format demandé par `PIPELINE.md` (espace après les deux-points) → corrigée. Le pipeline automatique de bout en bout (sans aucune intervention manuelle autre que ces correctifs) est maintenant confirmé fonctionnel.

**Aucun blocage actuel.** Points de vigilance identifiés :
- (2026-08-30) le job launchd `checkvalidation` tourne en tâche de fond sur le même dépôt local que les sessions interactives — une session qui modifie l'arbre de travail (ex. résolution de conflit `git merge` en cours) pendant qu'un sondage `checkvalidation` se déclenche peut faire committer un état intermédiaire non désiré (`git add -A` de `publish.sh` ne fait pas la différence). Le chemin de code `--bg` du CLI Claude Code supprime cette variable sur macOS d'après une inspection du binaire installé ; notre invocation utilise `-p` simple (a priori non concerné), mais si l'erreur d'authentification revenait malgré le jeton en place, c'est la première piste à vérifier.
- (2026-09-06) `~/Library/LaunchAgents/com.fabien.blogphoto.publication.plist` (copie déployée, hors dépôt) et `automation/com.fabien.blogphoto.publication.plist` (copie versionnée) divergent désormais intentionnellement (la première porte le jeton, pas la seconde) — un futur "redéploiement" de la copie versionnée par-dessus la déployée écraserait le jeton et referait planter l'automatisation.
